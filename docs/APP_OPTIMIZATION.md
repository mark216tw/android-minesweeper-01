# 踩地雷 APP 優化建議

## 文件目的

本文件根據目前 Pre-release 實作，整理介面、操作、功能、可靠性、效能與無障礙的改善方向，作為後續版本規劃依據。

優先級定義：

| 優先級 | 定義 |
|---|---|
| P0 | 正式發布前應優先處理，涉及資料一致性或核心可用性 |
| P1 | 明顯改善主要使用體驗，建議下一個 Pre-release 完成 |
| P2 | 提升留存、完整度與維護品質 |
| P3 | 長期產品功能，可依使用者回饋評估 |

## 優先級摘要

| 優先級 | 項目 | 主要效益 | 預估規模 |
|---|---|---|---|
| P0 | 棋局存檔序列化 | 避免存檔倒退、完成棋局復活或重複紀錄 | 中 |
| P0 | 棋盤縮放與平移邊界 | 避免棋盤移出畫面及手勢後誤觸 | 中 |
| P0 | 棋盤無障礙操作 | 讓 TalkBack 使用者可辨識並操作格子 | 中至大 |
| P1 | 響應式版面 | 改善小螢幕、橫向、分割畫面與大字體 | 中 |
| P1 | 計時與棋盤狀態分離 | 降低大型棋盤重組、耗電與重繪 | 中 |
| P1 | 自訂棋盤精確輸入 | 更容易設定尺寸與大量地雷 | 小至中 |
| P1 | 存檔損毀復原 | 避免載入卡住或因舊資料崩潰 | 小至中 |

## P0：發布前核心改善

### 1. 棋局存檔一致性

目前每次探索或插旗都會啟動新的 IO coroutine 寫入完整棋局，完成遊戲時則新增結果並清除進行中棋局。非同步工作若以不同順序完成，舊棋局可能覆蓋較新的狀態。

相關程式：

- `app/src/main/java/com/tainanlins5/minesweeper/GameViewModel.kt`
- `app/src/main/java/com/tainanlins5/minesweeper/data/GameRepository.kt`
- `app/src/main/java/com/tainanlins5/minesweeper/data/GameDao.kt`

建議：

- 以 `Mutex`、`Channel` 或單一 actor 串行化存檔。
- 為每局加入 `gameId` 與遞增 `revision`，拒絕舊 revision 覆蓋新資料。
- 將「寫入勝負紀錄」與「清除進行中棋局」包在同一個 Room transaction。
- ViewModel 狀態只由主執行緒修改，IO dispatcher 僅執行資料存取。
- 暫停 APP、遊戲結束與開始新局時立即寫入，其餘高頻操作可合併保存。
- 新遊戲建立期間暫時停用重複提交。

驗收條件：

- 連續操作後強制關閉 APP，恢復狀態不得倒退。
- 勝利或失敗後重新啟動，不得恢復該局為進行中。
- 快速連按重新開始不產生重複放棄紀錄。
- 完成紀錄與清除存檔具備交易一致性。

### 2. 棋盤縮放、平移與手勢安全

目前棋盤已能依縮放和平移換算正確點擊格，但平移量沒有邊界，棋盤仍可能完全移出可視區。縮放及拖曳結束後也需要實機確認不會觸發開格。

相關程式：`app/src/main/java/com/tainanlins5/minesweeper/ui/GameBoard.kt`

建議：

- 依縮放後棋盤尺寸限制 X、Y 平移範圍。
- 棋盤完整符合畫面時停用該軸平移。
- 至少保留一列及一欄可見，避免棋盤完全消失。
- 使用雙指中心點作為縮放焦點，使目標區域留在手指下方。
- 手勢超過 touch slop 後取消點擊；多指手勢結束時不得開格或插旗。
- 加入可操作的放大、縮小按鈕，保留既有置中功能。
- 棋盤格過小時，第一次點擊可先放大該區域，降低高級棋盤誤觸。

驗收條件：

- 30 × 24 棋盤在直式及橫式都能操作所有格子。
- 任意縮放及拖曳後，棋盤不會完全離開畫面。
- 雙指縮放及拖曳不會意外探索或插旗。
- 點擊位置在所有縮放比例下都與反應格一致。

### 3. TalkBack 與無障礙棋盤

棋盤使用單一 Canvas 繪製，目前缺少每一格的語意節點。TalkBack 無法知道格子座標、狀態、數字或可執行動作。

建議：

- 為每格提供列、欄及狀態描述，例如「第 3 列第 5 欄，未開啟」。
- 已開啟數字需讀出相鄰地雷數。
- 提供探索、快速展開、插旗及取消旗幟動作。
- 若大量虛擬節點影響效能，可新增無障礙游標模式，以方向控制搭配探索及插旗按鈕。
- 計時器、剩餘地雷與表情重新開始按鈕加入明確用途描述。
- 所有自製按鈕設定 Button role、選取狀態及狀態描述。
- 主題色不能是唯一狀態提示，必須保留圖示與文字。

驗收條件：

- TalkBack 可讀出目前格子的座標與狀態。
- 不使用觸控探索也能完成探索、插旗及快速展開。
- 計時更新不會持續打斷 TalkBack 播報。
- 所有主要按鈕皆具有名稱、角色與狀態。

## P1：核心體驗改善

### 4. 響應式直橫向版面

目前主要依直式或橫式切換版面，橫向側欄使用固定寬度。小型橫向手機、分割畫面、平板或大字體可能產生擁擠。

建議：

- 使用實際可用寬高或 Window Size Class 決定版面，不只判斷方向。
- 小型橫向畫面隱藏英文副標題並縮減非必要間距。
- 頂端圖示不足一列時改為兩列或可彈性換行配置。
- 對話框在矮橫向畫面保持可捲動，主要動作固定可見。
- 測試 `fontScale` 1.0、1.3、1.5 及 2.0。
- 平板限制棋盤最大顯示寬度，避免操作控制距離過遠。

驗收條件：

- 320 × 480 dp、480 × 320 dp 與分割畫面不裁切主要操作。
- 200% 字體下文字不重疊，核心操作仍可到達。
- 旋轉畫面不遺失棋局或產生重複結果。

### 5. 計時器與棋盤狀態分離

目前計時每 250 ms 更新完整 `GameState`，會使遊戲畫面重新組合並使 Canvas 重繪。大型棋盤會產生不必要的 CPU 與耗電。

建議：

- 將棋盤狀態與顯示時間拆成不同 StateFlow。
- 顯示時間每秒更新一次即可。
- 暫停、恢復、結束及保存時再計算精確毫秒數。
- 讓 GameBoard 只在格子、尺寸、遊戲狀態或配色改變時重繪。
- 快取繪製數字所需的 Paint 或字形資料。

驗收條件：

- 單純時間跳動不會導致棋盤重新繪製。
- 遊戲結果時間誤差小於一秒。
- 30 × 24 棋盤操作時沒有明顯延遲或持續高耗電。

### 6. 自訂棋盤精確輸入

目前寬度、高度與地雷數以 Slider 調整。當地雷上限較高時，很難選到特定數值。

建議：

- 每個欄位提供減號、數字輸入及加號。
- Slider 保留為快速調整方式。
- 加入常用密度捷徑，例如 12%、16%、20% 及 25%。
- 非法數值在欄位旁顯示原因，並停用開始與儲存按鈕。
- 已儲存項目支援重新命名或覆寫。
- 刪除預設提供確認或 Snackbar 復原。
- 儲存成功訊息必須在 DataStore 寫入成功後才顯示。
- 達到 3 組上限或內容重複時，直接停用按鈕並說明原因。

### 7. 存檔解析與載入錯誤復原

目前棋局還原會解析 enum、十六進位格子內容與棋盤尺寸。資料損毀或未來格式變更可能造成例外，初始化失敗也可能停留在載入畫面。

建議：

- 驗證棋盤尺寸、地雷數、字串長度、hex 格式、enum 及格子數。
- 還原失敗時清除損毀的 active game，建立安全的初級棋局。
- 初始化使用 `try/catch/finally`，確保載入狀態必定結束。
- 顯示可理解的錯誤訊息並提供重試或重設棋局。
- 啟用 Room schema export，資料庫版本更新時加入 migration 測試。

### 8. 視覺層級與操作提示

建議：

- 為按鈕定義主要、次要、切換與破壞性四種樣式。
- 選取勾選圖示使用固定空間，避免文字位置跳動。
- 插旗模式啟用時持續顯示「點按：插旗」。
- 七段顯示器加入地雷及時間圖示或文字標籤。
- 遊戲結果視窗增加難度、尺寸、地雷數及分享按鈕。
- 玩法說明拆成探索、插旗、快速展開與縮放四個區塊。
- 將 Kotlin 中的使用者文字移到 `strings.xml`，方便一致管理及未來翻譯。

### 9. 深色與高對比色彩

目前數字 1 至 8 使用經典固定色彩，部分深藍、深紅或深綠在暗灰背景上可能不易辨識。

建議：

- 深色模式使用獨立的高亮數字色盤。
- 為主題色與前景文字加入自動化對比測試。
- 錯旗、爆炸及結果不能只用顏色辨識，應搭配形狀或圖示。
- 預設色圓點至少使用 48 × 48 dp 觸控區域，並加入色名與選取語意。
- 增加高對比棋盤選項。

## P2：功能完整度與留存

### 10. 遊戲紀錄與統計

目前紀錄依時間排序，並以綠色勝利、紅色失敗及橘色放棄標籤區隔。

建議：

- 加入全部、勝利、失敗及放棄篩選。
- 顯示總局數、勝率、目前連勝與最長連勝。
- 為標準難度顯示最佳時間及「新紀錄」。
- 自訂棋盤最佳時間依寬、高及地雷數分組。
- 提供單筆刪除與 Snackbar 復原。
- 紀錄數量增加後改用 Room Paging 或分頁查詢。
- 為日期、難度及結果欄位建立索引。

### 11. 分享、剪貼簿與音效

建議：

- 分享前確認裝置有可處理 Intent 的 APP。
- 捕捉分享失敗，顯示 Snackbar 並提供複製替代方案。
- 安全取得 ClipboardManager，避免直接強制轉型。
- 使用 Snackbar 取代短暫 Toast，提升可見性與無障礙播報。
- 遊戲音效改用 SoundPool 及合適的 AudioAttributes。
- 關閉音效時不初始化播放器；音效失敗不得影響遊戲。

### 12. 全螢幕安全區

建議：

- 全螢幕仍保留 display cutout 及 mandatory gesture insets。
- 第一次開啟全螢幕時顯示一次性操作提示。
- 系統列暫時顯示時不得遮住重要按鈕。
- 確保全螢幕狀態除了顏色外，也有清楚圖示變化。

## P3：未來功能方向

- 固定 seed 的每日挑戰與可分享挑戰代碼。
- 棋局重播、錯誤分析與邏輯提示。
- 可選的無猜解棋盤模式。
- 遊戲紀錄 JSON 或 CSV 匯出與匯入。
- 不需網路的分享成績圖片。
- 鍵盤方向操作、Enter 探索及滑鼠右鍵插旗。
- 折疊裝置、ChromeOS 及平板專屬版面。
- 色弱、高對比、降低動畫及單手操作模式。
- 可調整棋盤格尺寸與其他復古棋盤外觀。

## 建議交付順序

### 階段一：可靠性

- 棋局存檔序列化與 Room transaction。
- 損毀資料復原。
- 分享及資料服務例外處理。
- 對應單元測試與整合測試。

### 階段二：棋盤操作

- 平移邊界與焦點縮放。
- 手勢誤觸防護。
- 放大、縮小及置中控制。
- 棋盤 TalkBack 操作。

### 階段三：介面與效能

- Window Size Class 響應式版面。
- 大字體及安全區支援。
- 計時與棋盤狀態分離。
- 深色高對比色盤及完整語意。

### 階段四：功能深化

- 自訂棋盤精確輸入。
- 紀錄篩選、統計及最佳時間。
- 每日挑戰、重播或匯出等長期功能。

## 建議測試補強

目前已有遊戲引擎、棋盤座標及自訂棋盤編碼測試。後續建議增加：

- 存檔寫入順序及完成交易測試。
- 損毀與舊版棋局資料復原測試。
- ViewModel 暫停、恢復、旋轉及重建測試。
- 縮放、拖曳與點擊衝突的 Compose UI 測試。
- 直式、橫式、分割畫面及平板截圖測試。
- 200% 字體與 TalkBack 語意測試。
- 淺色、深色及自訂色的對比測試。
- 分享目標不存在及剪貼簿服務異常測試。

## 成效指標

建議使用以下指標判斷優化是否有效：

- 棋盤誤觸與點擊錯位問題數量。
- APP 啟動、恢復及存檔失敗率。
- 高級與自訂棋盤完成率。
- 平均每局操作延遲與大型棋盤重繪次數。
- 自訂棋盤預設使用率。
- 遊戲紀錄查看、複製及分享使用率。
- TalkBack、大字體及橫向模式的可完成率。

本 APP 不使用分析或追蹤 SDK；若要取得上述產品指標，應優先採用本機、匿名、可由使用者主動匯出的診斷資訊，不應改變目前的離線與隱私定位。
