# 踩地雷 APP 優化待辦事項

## 使用方式

- 依階段與優先級由上至下執行。
- 完成實作、驗收條件與測試後，才將主項目標記為完成。
- 優先級：P0 為正式發布前必要項目；P1 為下一個 Pre-release；P2 為完整度與維護改善；P3 為長期功能。
- 規模：小、 中、 大為初步估算，實作前仍需確認影響範圍。

## 階段一：可靠性

### [ ] P0 棋局存檔一致性（中）

目標：避免存檔倒退、完成棋局復活或產生重複紀錄。

相關程式：

- `app/src/main/java/com/tainanlins5/minesweeper/GameViewModel.kt`
- `app/src/main/java/com/tainanlins5/minesweeper/data/GameRepository.kt`
- `app/src/main/java/com/tainanlins5/minesweeper/data/GameDao.kt`

實作：

- [ ] 使用 `Mutex`、`Channel` 或單一 actor 串行化存檔。
- [ ] 為每局加入 `gameId` 與遞增 `revision`，拒絕舊 revision 覆蓋新資料。
- [ ] 將「寫入勝負紀錄」與「清除進行中棋局」放入同一個 Room transaction。
- [ ] ViewModel 狀態只在主執行緒修改，IO dispatcher 僅負責資料存取。
- [ ] APP 暫停、遊戲結束及開始新局時立即保存，其餘高頻操作合併保存。
- [ ] 新遊戲建立期間停用重複提交。

驗收與測試：

- [ ] 連續操作後強制關閉 APP，恢復狀態不會倒退。
- [ ] 勝利或失敗後重新啟動，不會將該局恢復為進行中。
- [ ] 快速連按重新開始不會產生重複放棄紀錄。
- [ ] 完成紀錄與清除存檔具備交易一致性。
- [ ] 增加存檔寫入順序與完成交易測試。
- [ ] 增加 ViewModel 暫停、恢復、旋轉及重建測試。

### [ ] P1 存檔解析與載入錯誤復原（小至中）

目標：避免損毀或舊版資料造成崩潰、初始化失敗或永久停留在載入畫面。

實作：

- [ ] 驗證棋盤尺寸、地雷數、字串長度、hex 格式、enum 及格子數。
- [ ] 還原失敗時清除損毀的 active game，並建立安全的初級棋局。
- [ ] 初始化使用 `try/catch/finally`，確保載入狀態必定結束。
- [ ] 顯示可理解的錯誤訊息，並提供重試或重設棋局。
- [ ] 啟用 Room schema export。
- [ ] 資料庫版本更新時加入 migration 測試。

驗收與測試：

- [ ] 增加損毀棋局資料復原測試。
- [ ] 增加舊版棋局資料相容或安全重設測試。
- [ ] 確認任何初始化例外都不會讓載入畫面無限顯示。

### [ ] P2 分享、剪貼簿與音效錯誤處理（小）

目標：避免裝置與系統服務差異造成崩潰或操作無回應。

實作：

- [ ] 分享前確認裝置存在可處理 Intent 的 APP。
- [ ] 捕捉分享失敗，顯示 Snackbar 並提供複製替代方案。
- [ ] 安全取得 `ClipboardManager`，避免直接強制轉型。
- [ ] 使用 Snackbar 取代短暫 Toast，改善可見性與無障礙播報。
- [ ] 遊戲音效改用 `SoundPool` 與合適的 `AudioAttributes`。
- [ ] 關閉音效時不初始化播放器。
- [ ] 確保音效初始化或播放失敗不影響遊戲。

驗收與測試：

- [ ] 增加分享目標不存在的測試。
- [ ] 增加剪貼簿服務異常的測試。
- [ ] 確認音效不可用時仍可正常完成遊戲。

## 階段二：棋盤操作

### [ ] P0 棋盤縮放、平移與手勢安全（中）

目標：避免棋盤移出畫面、點擊錯位及縮放或拖曳後誤觸。

相關程式：`app/src/main/java/com/tainanlins5/minesweeper/ui/GameBoard.kt`

實作：

- [ ] 依縮放後棋盤尺寸限制 X、Y 平移範圍。
- [ ] 棋盤完整符合畫面時停用該軸平移。
- [ ] 至少保留一列及一欄可見，避免棋盤完全離開畫面。
- [ ] 使用雙指中心點作為縮放焦點，使目標區域留在手指下方。
- [ ] 手勢超過 touch slop 後取消點擊。
- [ ] 多指手勢結束時不得探索或插旗。
- [ ] 加入可操作的放大與縮小按鈕，保留既有置中功能。
- [ ] 棋盤格過小時，評估第一次點擊先放大目標區域。

驗收與測試：

- [ ] 30 x 24 棋盤在直式及橫式都能操作所有格子。
- [ ] 任意縮放及拖曳後，棋盤不會完全離開畫面。
- [ ] 雙指縮放及拖曳不會意外探索或插旗。
- [ ] 所有縮放比例下，點擊位置都與反應格一致。
- [ ] 增加縮放、拖曳與點擊衝突的 Compose UI 測試。

### [ ] P0 TalkBack 與無障礙棋盤（中至大）

目標：讓 TalkBack 使用者能辨識格子狀態並完成所有核心操作。

實作：

- [ ] 為每格提供列、欄及狀態描述，例如「第 3 列第 5 欄，未開啟」。
- [ ] 已開啟數字需讀出相鄰地雷數。
- [ ] 提供探索、快速展開、插旗及取消旗幟動作。
- [ ] 若大量虛擬節點影響效能，改用無障礙游標模式與方向控制。
- [ ] 為計時器、剩餘地雷與表情重新開始按鈕加入明確用途描述。
- [ ] 所有自製按鈕設定 Button role、選取狀態及狀態描述。
- [ ] 確保主題色不是唯一的狀態提示，保留圖示與文字。

驗收與測試：

- [ ] TalkBack 可讀出目前格子的座標與狀態。
- [ ] 不使用觸控探索也能完成探索、插旗及快速展開。
- [ ] 計時更新不會持續打斷 TalkBack 播報。
- [ ] 所有主要按鈕皆具有名稱、角色與狀態。
- [ ] 增加 TalkBack 語意測試。

## 階段三：介面與效能

### [x] P1 可切換主介面版型（中）

- [x] 提供經典版與復古掌機版主介面。
- [x] 復古掌機版依直式、橫式配置底部或右側控制盤。
- [x] 使用 DataStore 保存版型選擇，重新啟動後仍會套用。

### [ ] P1 響應式直橫向版面（中）

目標：支援小螢幕、橫向、分割畫面、平板及大字體。

實作：

- [ ] 使用實際可用寬高或 Window Size Class 決定版面，不只判斷方向。
- [ ] 小型橫向畫面隱藏英文副標題並縮減非必要間距。
- [ ] 頂端圖示空間不足時改為兩列或可彈性換行配置。
- [ ] 對話框在矮橫向畫面保持可捲動，且主要動作固定可見。
- [ ] 平板限制棋盤最大顯示寬度，避免操作控制距離過遠。

驗收與測試：

- [ ] 320 x 480 dp、480 x 320 dp 與分割畫面不裁切主要操作。
- [ ] 測試 `fontScale` 1.0、1.3、1.5 及 2.0。
- [ ] 200% 字體下文字不重疊，核心操作仍可到達。
- [ ] 旋轉畫面不會遺失棋局或產生重複結果。
- [ ] 增加直式、橫式、分割畫面及平板截圖測試。

### [ ] P1 計時器與棋盤狀態分離（中）

目標：降低大型棋盤不必要的重組、重繪、CPU 使用量與耗電。

實作：

- [x] 將棋盤狀態與顯示時間拆成不同 `StateFlow`。
- [x] 顯示時間改為每秒更新一次。
- [x] 暫停、恢復、結束及保存時再計算精確毫秒數。
- [x] `GameBoard` 只在格子、尺寸、遊戲狀態或配色改變時重繪。
- [x] 快取繪製數字所需的 Paint 或字形資料。

驗收與測試：

- [x] 單純時間跳動不會導致棋盤重新繪製。
- [x] 遊戲結果時間誤差小於一秒。
- [ ] 30 x 24 棋盤操作時沒有明顯延遲或持續高耗電。

### [ ] P1 視覺層級與操作提示（小至中）

- [ ] 為按鈕定義主要、次要、切換與破壞性四種樣式。
- [ ] 選取勾選圖示使用固定空間，避免文字位置跳動。

### [ ] P1 深色與高對比色彩（小至中）

- [ ] 為主題色與前景文字加入自動化對比測試。

- [ ] 增加高對比棋盤選項。

### [ ] P2 全螢幕安全區（小）

- [ ] 全螢幕仍保留 display cutout 與 mandatory gesture insets。
